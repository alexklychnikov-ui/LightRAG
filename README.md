# LightRAG + Telegram Bot


![Mockup](docs/mockups/generated-2-20260506-150550.png)

Готовое решение для **личной или корпоративной базы знаний**, где:
- все важные материалы (заметки, файлы, статьи, документация, ссылки) складываются в LightRAG;
- Telegram‑бот становится единым интерфейсом доступа к знаниям;
- ответы готовятся с учетом **вашей** базы, а не абстрактного интернета.

Подходит для технических фаундеров, тимлидов и консультантов, которым нужна:
- централизованная БЗ (проектные заметки, инструкции, статьи);
- быстрая Q&A‑поддержка прямо из Telegram;
- управляемая интеграция с LLM (RAG + модель как помощник, а не “мутный черный ящик”).

---

## Как пополняется база знаний

Бот работает в режиме **“инбокс для знаний”**: все, что вы ему присылаете, уходит в LightRAG.

- **Текстовые сообщения**
  - Выбираете режим `Пополнить БЗ`.
  - Отправляете фрагмент текста, конспект, переписку, заметку.
  - Бот:
    - валидирует размер;
    - при необходимости **делает технический перевод на русский** (если включен `BOT_TRANSLATE_TO_RU`): сохраняются команды, код, CLI, идентификаторы; смысл текста максимально близок к оригиналу;
    - отправляет текст в LightRAG `/documents/text`;
    - запускает трекинг обработки (по `track_id`).
  - В ответ:
    - сообщение о постановке задачи в обработку;
    - затем — уведомления об этапах (`обрабатывается`, `обработан`, `обработан с ошибками`) по данным `/documents/track_status/{track_id}`.

- **Файлы**
  - Поддерживаются текстовые и бинарные файлы (PDF, DOCX и т.п.).
  - Для **текстоподобных** файлов:
    - бот вытаскивает содержимое, проверяет, нужен ли перевод;
    - при необходимости переводит (с сохранением команд, нод, API‑имен);
    - отправляет в LightRAG как текстовый документ.
  - Для остальных:
    - отправляет файл как есть на `/documents/upload` (с fallback на `/documents/file`).
  - Всегда возвращается человекочитаемый ответ: лимиты, статус, ID задачи и т.п.

- **URL (ссылки на сайты)**
  - В режиме `Пополнить БЗ` можно отправить **любую HTTP/HTTPS ссылку**.
  - Бот:
    - проверяет, что это публичный адрес (SSRF‑защита: блокировка локальных/приватных IP, редиректов внутрь сети);
    - скачивает страницу с лимитом по размеру;
    - парсит HTML (BeautifulSoup) и извлекает **значимую текстовую часть**;
    - **обходит внутренние ссылки того же сайта** (`<a href>` на тот же `host`): по очереди открывает ограниченное число страниц, вытаскивает с каждой полезный текст и склеивает в один документ (разделитель `---`), чтобы в базу попала не только «обложка», но и связанные статьи/разделы;
    - при включенном переводе — делает технический перевод на русский;
    - отправляет результат в LightRAG как обычный текстовый документ.

Во всех трёх случаях база знаний пополняется **одним и тем же API** LightRAG, а Telegram‑бот отвечает за:
- нормализацию входа (текст/файл/URL);
- перевод при необходимости;
- безопасную доставку в RAG и трекинг статуса.

## Как работает Q&A в Telegram

Режим `Задать вопрос` превращает бота в **помощника поверх вашей БЗ**.

- **Контекст Q&A в чате**: пары «вопрос — ответ» подставляются в следующий запрос к LightRAG (и во внешний fallback модели), чтобы можно было уточнять «а это что?», «раскрой пункт 2» без повторения всей предыстории. Сброс: команда `/forgetctx` (или `/forget_context`), полный сброс при `/start`. Автоочистка после простоя настраивается `BOT_QA_SESSION_IDLE_MINUTES`.

- При каждом вопросе:
  - бот вычисляет стартовый режим поиска (`mix` по умолчанию либо ваш выбор через `/qmode` или inline‑кнопку);
  - запускает цепочку `mix -> hybrid -> global -> naive`;
  - если все ответы из LightRAG выглядят “слабыми” (нет информации, не могу ответить) — добавляет финальный запрос к модели **вне RAG** (OpenAI).

- В ответ вы всегда видите:
  - **режим поиска** с перечислением реально проверенных режимов (например, `mix (проверено: mix,hybrid,global,naive)`);
  - **источник ответа**:
    - `LightRAG` — ответ на основе вашей базы знаний;
    - `модель (вне RAG)` — прямой ответ модели, когда в БЗ информации не хватает;
  - **режим ответа**: `оригинал` или `перевод` (если финальный текст дополнительно переведен на русский).

Плюсы для заказчика:
- понятная и прозрачная трассировка: видно, использовалась ли база знаний или только модель;
- fallback‑логика снижает количество “я не знаю” без превращения системы в чистый ChatGPT;
- можно строить поверх этого **диалоговые сценарии**: уточнять, переформулировать, просить примеры, не меняя архитектуру.

## Telegram‑интерфейс

- **Постоянная кнопка `Меню`** (ReplyKeyboard):
  - всегда доступна снизу чата;
  - возвращает в режим выбора.

- **Inline‑меню режимов**:
  - `Пополнить БЗ` — включает ingest‑режим;
  - `Задать вопрос` — включает Q&A с выбором retrieval‑режима;
  - `Статус` — проверка `/health` LightRAG + показ runtime‑метрик бота.

- **Выбор режима поиска (Q&A)**:
  - кнопки: `mix`, `hybrid`, `global`, `local`, `naive`, `auto`;
  - команда `/qmode <mode>` или inline‑формат `режим:<mode> | вопрос`.

Интерфейс заточен под **ежедневное использование**: минимум команд, всё управляется кнопками и короткими подсказками.

## Надежность и эксплуатация

- **Rate limiting**:
  - per‑chat лимиты с окном (`BOT_RATE_LIMIT_MAX_EVENTS`, `BOT_RATE_LIMIT_WINDOW_SECONDS`);
  - аккуратные сообщения пользователю с временем ожидания.

- **HTTP‑устойчивость**:
  - retries с экспоненциальной задержкой и учётом `Retry-After` для `429`;
  - ingest‑запросы (`/documents/*`) **без повторных попыток**, чтобы не дублировать документы.

- **Мониторинг и статус**:
  - встроенный `BotRuntimeMetrics` (счётчики ingest/Q&A/ошибок/ratelimit);
  - выводится в режиме `Статус` вместе с `/health` LightRAG.

- **Безопасность**:
  - авторизация в LightRAG через `X-API-Key`;
  - строгая обработка ошибок без утечек внутренних деталей пользователю;
  - SSRF‑защита для URL‑ingest.

## Переменные окружения

**Минимально достаточно:**
- `TELEGRAM_BOT_TOKEN`
- `LIGHTRAG_URL`
- `LIGHTRAG_API_KEY`

**Рекомендуемые опции:**
- `TELEGRAM_BOT_CHATID`
- `BOT_TRANSLATE_TO_RU=true|false`
- `BOT_QUERY_MODE=mix|hybrid|global|local|naive`
- `BOT_QUERY_FALLBACK_MODES=hybrid,global`
- `BOT_ENABLE_OPENAI_FALLBACK=true|false` (если `true`, после слабого ответа RAG идет прямой запрос к модели)
- `OPENAI_API_KEY` (нужен для fallback вне RAG)
- `BOT_OPENAI_MODEL=gpt-4o-mini`
- `OPENAI_API_BASE_URL=https://api.openai.com/v1` (опционально для кастомного провайдера)
- `BOT_URL_FOLLOW_MAX_PAGES=6` (максимум HTTP‑запросов при разборе одной ссылки из Telegram)
- `BOT_URL_FOLLOW_DEPTH=1` (глубина обхода: `0` — только входная страница; `1` — дополнительно страницы по ссылкам **с входной**; `2` — ещё уровень по ссылкам с уже открытых страниц того же сайта, пока не исчерпан лимит страниц)
- `BOT_URL_FOLLOW_MAX_LINKS=24` (сколько разных `href` рассматривать при обходе)
- `BOT_QA_SESSION_IDLE_MINUTES=20` (через сколько минут **без сообщений в Q&A** сбросить контекст чата; `0` / `off` / `false` — не сбрасывать по таймеру; фоновая очистка раз в минуту)
- `BOT_QA_CONTEXT_MAX_MESSAGES=24` (максимум сохранённых реплик user+assistant, старые отбрасываются)
- `BOT_QA_CONTEXT_MAX_CHARS=7000` (ограничение суммарной длины блока контекста при подстановке в запрос)
- `BOT_RATE_LIMIT_MAX_EVENTS=6`
- `BOT_RATE_LIMIT_WINDOW_SECONDS=30`
- `BOT_HTTP_RETRY_ATTEMPTS=2`
- `BOT_HTTP_RETRY_BACKOFF=0.7`

## Деплой бота на VPS (Docker)

```powershell
powershell -ExecutionPolicy Bypass -File ".agent-remote/deploy-telegram-bot.ps1"
```

Скрипт:
- заливает обновлённый код на сервер;
- проверяет наличие ключевых переменных `.env`;
- пересобирает и перезапускает `telegram-bot` в Docker.
